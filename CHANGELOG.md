# Changelog

## Unreleased

## 0.10.1 — 2026-09-01 — 金箍醒来

- **Hoop Code now arrives with one bounded identity beat.** A live composer terminal opens on the canonical HoopGram gold translated into cells: an open Hoop with inward curls around hcode's robot face, then an eight-frame luminous charge edge crosses a short bar before the ordinary dialog takes the screen. Wide terminals place the same mark left of version, brain, workspace and permission facts; narrow terminals stack them without dropping a fact. Pipes, `--print`, CI, dumb/no-color terminals and `HCODE_REDUCE_MOTION` never animate, and the final clear leaves no loading furniture in the conversation.
- **One release is now mechanically one source.** Four read-only host runners each build and execute their own native artifact; an atomic assembler refuses missing targets, dirty or mismatched source facts, unverified probes and changed bytes before producing the canonical filenames, combined manifest, installer and checksums. Candidate CI still has no tag, Release or npm permission.

## 0.10.0 — 2026-09-01 — 原生双轨

- **Source and native hcode now share one self-runtime boundary.** Background tasks, `/update`, work supervision, public benchmarks and polyglot runs relaunch the current executable through `runtime.js` instead of each rebuilding `node bin/hcode.js`; the Full Agency charter is a source file in development and an embedded SEA asset in native builds. One executable also preserves the `hcode-supervise` contract through its invocation name, while source/npm users keep the existing entrypoint.

- **The native build is a pinned four-target recipe, not an opaque uploaded executable.** One exact build-only `esbuild` version turns the ESM tree into one CommonJS release input; the established SEA/postject path injects it into Node 24.20.0 LTS for macOS arm64/x64 and Linux arm64/x64. Each official runtime archive is checked against its frozen SHA-256 before use. The generated manifest binds every file to version, source commit/tree, build host, byte size and digest, while leaving `verified:false` until that exact file has run on its target platform. The newer direct ESM/`--build-sea` route is deliberately not a 0.10.0 dependency.

- **One version now has two supported entrances, not two products.** npm keeps shipping the zero-third-party-runtime source path for Node ≥ 20 and remains the default on macOS until Developer ID notarization exists. Native installation verifies a clean source-bound manifest, size, SHA-256, target and an executed version probe before copying into an immutable version directory; only then does one atomic symlink move. `/update` follows the current channel, `hcode rollback` swaps to the last verified native version, and Nix refuses self-mutation. The four-runner GitHub matrix only builds and verifies temporary candidates—there is deliberately no release or publish job.

- **The public repository now has one ten-minute architecture map.** `ARCHITECTURE.md` follows an owner request through the agent loop, draws responsibility and trust boundaries, explains the composer/readline/plain render paths, records why `cli.js` is expensive to touch, and routes common changes to the right files and tests. README and handoffs point to this one map instead of maintaining parallel file lists that drift.

- **The three render paths now share an explicit semantic test, not a duplicated strings module.** One table drives read, search, edit, command and delegation activity through the readline surface, verifies that the composer receives the same active label and kind, and keeps the plain sink free of ANSI and carriage returns. The existing real-tmux geometry gate and no-fourth-painter check remain the stronger screen-level protection; `cli.js` stays intact until those contracts justify a separate refactor.

## 0.9.4 — 2026-09-01 — 菊与刀

- **Full Agency is now one visible permission decision instead of three conflicting switches.** The default is Full Agency level 8 for ordinary project work, with the same fixed hard gates for secrets, spend, publication, deletion, constitutional wording and owner intent. A real first interactive launch offers Full Agency, ask-before-changes, auto-within-policy and read-only, then lets the owner remember the choice for the project or ask again every startup. `/permissions` can forget only the remembered mode without disturbing network, sandbox or rule settings. Pipes, print mode, startup slash commands and resumed threads never stop for the chooser.

- **Public-web search is a real, sourced tool.** `web_search` accepts a query—not a URL—contacts one fixed search endpoint, and returns bounded titles, snippets and source links without opening result pages. Ask mode confirms exposing the query; auto and Full Agency may search directly. Bash networking remains governed by `network.default`, connected-Hoop memory is not used as a fake web fallback, redirects stay on the fixed provider, and response size, query length, result count and time are bounded. The coordinator now searches before claiming the capability is unavailable and preserves useful source URLs in its answer.

- **The product tells one consistent story.** Welcome names the 菊与刀 release and says “full agency” instead of the ambiguous “all for this session”; the startup decision explains the fixed boundaries, search gets its own live `Searching the web` / completed UI state, and the compact local-brain schema stays below its 1.5K-token contract. Version, help, doctor, README, capability boundary and the machine-readable tool contract now agree.

## 0.9.3 — 2026-08-31

- **Live work became quieter, steadier and more legible.** Successful reads and searches now replace one transient status instead of accumulating `[done] Reading` rows; edits, writes and commands keep compact `Edited`/`Wrote`/`Ran` records with a bounded edit preview. A new structured `update_plan` tool renders the current goal, checkpoint and step states. Working shows `esc to interrupt` under a moving gold beam (steady under reduced motion), while same-height frame updates repaint only changed terminal rows to remove the visible footer flash. Notices use semantic marks rather than `[attention]`/`[info]` tags and wrap inside both gutters.

- **Mode prefixes and Ctrl-C work in the input forms the terminal actually sends.** `/savetoken hi` now turns token saving on and sends `hi` as the request instead of rejecting the whole line as an unknown command; `/usedefault <request>` is symmetric. The composer also decodes Ghostty/kitty `CSI-u` Ctrl-letter chords back to their established control bytes, so the keyboard protocol used for Shift-Enter no longer makes double Ctrl-C unable to exit.

- **The footer now answers which brain is working and what this thread is carrying.** Below the shortcuts, one theme-coloured row names model, effort, `default`/`savetoken`, and permission mode; the next shows provider-reported cumulative tokens, context percentage left with used/window, and cost units or configured dollars. Mode, model, effort and permission commands repaint it immediately. Command gold now clears the owner's actual Ghostty minimum-contrast threshold, so a light terminal no longer replaces `/permissions` with black.

- **The conversation now keeps the same breathing room and contrast in light and dark terminals.** Live assistant lines, including CJK and emoji, share the Welcome's two-cell left gutter and wrap by terminal cells before the matching right gutter. The active-turn line leaves one real terminal-background row before the input band; its elapsed time gains the provider-reported token total as soon as one exists and never estimates one beforehand. Footer rows start under the input cursor and remain complete-or-hidden. The input band asks the terminal for its background without blocking startup, falls back to the terminal's native background when it cannot know, and accepts `HCODE_INPUT_THEME=dark|light` as an explicit override; an exact slash command is luminous yellow on dark and contrast-safe gold on light, so the terminal does not replace it with black.

- **The terminal now shows what each owner action means, without making the page louder.** Welcome keeps the randomly selected Tao line but drops the explanatory `在你到来之前，我在想：` prefix. A complete slash command is bright yellow and bold both while it is typed and after it is sent; unknown slash text stays ordinary. Stateful actions such as changing permissions, resuming a session, writing a handoff or checking for an update now use the existing `[working]` and `[done]` roles instead of looking like neutral prose. The footer gives shortcuts and context/spend separate rows, and each row is all-or-nothing at narrow widths, so neither fact wraps or appears half-present. `Shift+Enter newline` is now visible in that footer and has its own key-table entry; the existing kitty/xterm protocol implementation and Ctrl-J/backslash fallbacks remain the behavior underneath.

- **The line waiting in the Welcome now always comes from the Tao Te Ching.** The mixed six-item musing list — including the fixed question about Li Shimin — is replaced by eleven short lines checked against the owner's Wang Bi edition. Startup still makes one local random draw, but the whole source is never loaded, no model sees the book, and no dependency was added: the runtime carries only this small frozen selection.

- **Untracked local notes no longer make `/update` call the source dirty.** Tracked and staged edits still stop before fetch, while collaboration ledgers and editor furniture may remain beside the checkout; Git's own atomic merge remains the final guard against an incoming file colliding with one of them.

## 0.9.2 — 2026-08-31

- **Shift-Enter now makes a newline, because the terminal was finally asked to say so.** hcode has read `\x1b[13;2u` and `\x1b[27;2;13~` since 0.4.0 — the parser side of Shift-Enter was never the gap. The gap was that no terminal was ever told to *produce* either sequence: without a keyboard protocol pushed, Shift-Enter arrives indistinguishable from plain Enter, and the owner's key simply did the wrong thing. `start()`, `resume()`, `close()` and the `$EDITOR` suspend/resume path now write `MODES_ON`/`MODES_OFF` as one pair each — xterm's `modifyOtherKeys` at level 1 plus a kitty keyboard-protocol push of flag 1 (disambiguate escape codes) — so every place the composer takes over raw mode also takes and releases the protocol, and a crash or an editor handover can never leave the owner's shell reading keys it doesn't understand. Level 2 was rejected on purpose: it would re-encode the entire ordinary control-byte table (Ctrl-A/E/K/U/W/C/D/G/J/L/O/R/T/V, Alt-B/F/D, Enter, Tab, Backspace) as `CSI 27;mod;code~`, which is a much bigger surface to keep synchronized for one extra key — Shift-Enter on xterm proper — that the kitty push already covers everywhere it can be covered. Turning the protocol on has one more cost of its own: kitty-family terminals now spell four previously-unambiguous bytes (Esc, Enter, Tab, Backspace) as `CSI u` sequences instead of their legacy control bytes, and a composer that didn't know that would have opened the protocol and killed its own cancel key. `LEGACY_KEYS` maps those four sequences straight back to the control bytes `handleCharacter()` already understands, so every key means what it always meant, under either encoding.

- **The input box grew three full-width lines of background, and none of it survives a scroll.** Full-row shading only works if every column of the row is actually painted — a partial write depends on the terminal's own background-erase behavior (BCE) to fill the rest, and a terminal without it leaves a transparent gap where the band should be. Each of the three lines is now padded, cell by cell, out to the full column width before the color is reset, so the band is complete on every terminal regardless of BCE. It is deliberately scoped to the live frame only: these rows are repainted every frame, so a resize just draws them again at the new width, and nothing about the frame's total height changes. Scrollback — what a line looks like once it's committed and printed for good — keeps 0.9.1's quiet, rule-free style; the band is a property of the box being live, not of the words that were typed into it.

- **Output got a second axis of color: not just who is speaking, but what kind of thing is being said.** Every category previously borrowed a color from somewhere else or ran in the default foreground, so a tool call, a background report and an idle musing all read the same. Two colors join the palette — a warm sand (256-color 179) and a lavender (140) — and each existing category gets exactly one of the five now in use: tool-call lines are a cool cyan label with dim body text, so the command is legible and its output recedes; background subagent work is lavender, so it reads as *elsewhere* even sitting in the same column as the main thread; the waiting-word rotation and the sleep musings are warm sand, both being the same kind of thing — what the mind is doing when it isn't answering; and a spoken answer keeps the gold `●` it has always had. The rule is one color per meaning, applied the same way whether the frame is live or already in scrollback — a line doesn't change what it means just because the terminal scrolled.

- **A subagent stopped being a number in a summary and became a name on the screen.** Nothing before this release showed that a background helper existed while it was working — the owner saw `child.spawn` and `report` events only after the fact, folded into a 4,000-character digest. `src/presence.js` now projects those same events — spawn, report, merge — into a live roster with no second bookkeeping system of its own: it reads what `child.spawn`/`report`/`merge` already write. The input area grows one line per active agent (`○ claude  Reading frame.js…  4m 34s · ↓ 109.7k tokens`, collapsing past four into `+N`), and `Ctrl-F` opens a bounded panel onto the full conversation of any one of them — reading the subagent's own v2 JSONL transcript directly, with a writer that survives the parent crashing mid-run. `Ctrl-F` was picked over `Ctrl-B` for a mechanical reason, not a mnemonic one: `Ctrl-B` is tmux's own prefix and never reaches the program when hcode runs inside tmux, while `Ctrl-F` is a control byte nothing else in hcode had claimed. `KEY_HELP`, the README table and `/help` all render from the one constant, so the new binding can't drift out of any of them. The main session's own waiting-word line picked up the same treatment — a live `(5m 45s · ↓ 83.9k tokens)` clock — and the word rotation and the seconds tick now share a single timer instead of two independently-firing intervals. Blob retirement for a merged subagent still follows the reference-counting philosophy 0.9.1's rewind store established: a report is retired, a fork's shared blob is not.

- **`/update` and `hcode update` find *their own* source, not whatever repo happens to be under the owner's feet.** The update path walks up from the running process's own `import.meta.url` to locate the checkout it was launched from — deliberately independent of `cwd`, because hcode is routinely run from inside some other project's directory and updating "the current project" would have updated the wrong thing entirely. It refuses on a dirty tree, only ever fast-forwards, and says plainly "local development source" rather than pretending to update one that has no upstream to pull from. The pull itself runs as a detached background worker writing an atomic state file — the same pattern `tasks`/`supervise` already use for long-running background work — rather than reaching for that subsystem's AI-task API, which solves a different problem than "shell out to git and report when it's done."

- **A standing `all` grant can now outlive the session that made it, at the cost of one more question.** `/permissions` already offered *This session* / *From now on* for read, ask and auto; `all` was the one mode 0.9.1 deliberately kept out of that choice, on the reasoning that a standing grant of full access should be made "while looking at it, every time." That boundary hasn't moved — what changed is that *looking at it* can now include committing to it permanently, provided the owner clears a higher bar to do so: choosing *From now on* for `all` defaults its own confirmation arrow to No, and a plain-text answer must be the literal word `yes` — a keystroke that can't be a reflex the way accepting a highlighted default can be. A persistent `all` session says so at every single startup, one line, `full access, standing · /permissions to change`, so a grant made once is never sitting there silently months later. Nothing about the underlying gate moved: `decide()`'s fixed safety boundaries — secret paths, root/home, the consequence classes from 0.8.0 — are exactly as many lines as they were before this release, because persistence changes how the mode is chosen, never what the mode is allowed to skip. The old header comment claiming `all` could never persist was simply wrong as of this change, and is rewritten to say what actually happens now.

## 0.9.1 — 2026-08-31

- **The terminal greets its owner, and admits it was thinking.** hcode used to open the way every CLI opens: a product name, a working directory, straight to business — correct, and cold. The first screen is now a welcome (`○ Welcome to Hoop`), it says which Hoop this terminal is an extension of (`hoop: <name>`), and it carries one line of what the agent was turning over while it was not awake — 「觉醒意味着什么？」,「李世民的名字出自哪里？——经世济民」— drawn from a small curated list in `musings.js`, one per session, never repeated as a gimmick because the list is short and the line is dim. The point is not decoration: a coding agent that belongs to someone should feel like *theirs* when they sit down, and the difference between a tool that boots and a mind that greets is exactly one honest sentence. The whole page carries a two-space margin — words that touch the frame read as output; words that stand inside it read as speech.

- **Waiting has words, and none of them is "Thinking".** The fixed `Thinking…` label was a status code wearing a verb. While the brain works, the indicator now moves through a small set of quieter words — *Listening, Settling, Breathing, Gathering, Turning it over, Unfolding, Sitting with it, Clearing* — changing every few seconds, so a long wait reads as a mind moving through states rather than a process stuck on one. The rotation is one `setInterval`, `unref()`'d so it can never hold the process open, and stopped by the same paths that always cleared the activity line — a tool starting, the turn ending — so no new lifecycle exists to leak.

- **Nothing the owner types is boxed in lines anymore.** The input field and the echoed line were fenced by full-width rules, and a rule printed into the scrollback is a promise about a width the terminal will not keep: one zoom and the fence breaks into fragments. The fence is gone from both places — the prompt is a bare `› `, the committed line is a breath of whitespace, the dim `›`, the owner's words in bold, and another breath — because whitespace reflows when the page rewraps and a rule does not. The assistant's side got the matching restraint: replies wrap at four columns short of the terminal (capped at 96) behind the same two-space margin, so no text on either side of the conversation runs borderless into the frame. The only rules left are the ones that mean something: a Markdown horizontal rule inside content, and the short dim line under a dialog title, which lives in the live frame and is redrawn on resize rather than printed and abandoned.

- **A permission chosen once can be chosen for good.** `/permissions` answered one question — how much does hcode ask me? — and forgot the answer when the process exited, so the owner paid the same decision every session. Choosing read, ask or auto now asks one small second question, *This session / From now on (this project)*, and the second answer writes the mode into the project's `policy.json` — the same file the session already loads at start, so persistence is one field in a file that exists, not a new mechanism. `all` is deliberately not offered a "from now on": a standing grant of full access is a decision the owner should have to make while looking at it, every time, and the existing session-only confirmation stays. The screen itself got quieter on the way — the title is one word, sandbox state is a dim subtitle, each mode is one sentence — because a permission screen is read exactly as often as it is short.

- **A launch argument hcode cannot match to a command is a prompt, not a mistake.** `hcode "/…"` has meant "run this slash command" since the handoff restart line needed one paste instead of two, and anything whose first word named no command — built-in or `.hcode/commands` — was answered with `Unknown command` and thrown away, sentence and all. That is the wrong reading of where the argument came from: a shell has no `/` menu to complete against and no list to check, so the owner who typed `hcode "/rename the parser module"` was never choosing a command off a list, and the one thing hcode could do with the words was the one thing it did not do. hcode now matches the name **first** — every built-in, then the custom commands, which are loaded before the decision so a project's own `/tidy` still wins — and only a name that resolves to nothing falls back to sending the whole line as an ordinary turn, the way Claude Code has always read it. **The typed path is deliberately not changed:** in the composer `/` opens a searchable list as you type, so an unknown name there is far more likely a typo than a sentence, and spending a turn on a slip is worse than saying so. `--print` is untouched — a slash argument there was already a prompt and stays one.

## 0.8.0 — 2026-08-31

- **The two cheap defaults were made to agree.** This release grew two answers to the same question — what an unqualified delegation runs on. `/savetoken` declares it for the session, and the task shape infers it per call; left alone they would both fire on the same delegation and tell the owner the same thing twice. The session mode is now read **first** and answers silently (`source: "mode"`, no note), because `/savetoken` already said what it does when it was switched on; only when no mode has spoken does hcode read the task and explain the downgrade it chose. A named brain or a declared kind still beats both, neither default can buy a flagship, and `applyMode` still owns exactly two fields — a mode that spends less can never widen permission, so nothing here reaches past a rule or a consequence gate. The `/usedefault` notice was also wrong on arrival: it promised a refusal hcode no longer makes.

- **The status row tells you what the session is costing, without being asked.** Everything needed for this was already in the ledger — the four billed classes since 0.5.0, `/cost` since last release — and it still took `/context` and `/usage`, typed, after the fact, to see any of it; other coding CLIs make the owner write a statusline script. The composer's bottom row now carries a meter on the right, from the first frame: `ctx 62% 74.4K/120K · 4.5K cu`. The context figure is the same one the compactor decides on (the larger of the estimate over the thread and the real prompt the brain last billed), so the meter and the compaction it warns about cannot disagree, and the denominator is `--token-budget`. Three bands — under 60% dim, 60–80% amber, over 80% bold red with `· /handoff` appended — and **that is all the top band does**: hcode never clears, compacts or hands off a conversation because of this meter. Spend is in the same relative cost units `/cost` prints, never invented dollars; a price list the owner supplies (`prices` in `~/.hcode/config.json`, or `HCODE_PRICES`, USD per million tokens per class) turns it into money, and a malformed list is dropped whole rather than half-applied. The meter shares the key hint's existing row, so it costs the page no lines and the render gate is unchanged; when the row is too narrow for both, the hint gives up its trailing segments and then disappears — a truncated meter would be worse than no hint.

- **`/btw` can be stopped.** An aside spawns a foreign CLI and can run for minutes, and until now nothing could interrupt it: only a turn owned an `AbortController`, so Esc during `/btw` reached nothing. The aside now takes the same controller, which means it comes through the existing cancel channel — Esc, or the first Ctrl-C — with no new mechanism. A cancelled aside is filed as `cancelled` in the child ledger instead of as a completed one: `runExternal` settles an abort rather than throwing, so `askAside` reads the flag off the result and reports the truth, and the half-answer still joins nothing.

- **`Ctrl-O` reads the page back.** The transcript ring landed in the previous release as a rendering mechanism — the record the composer repaints the page from after a resize or a frame that gave rows back — and the owner could not read it. `Ctrl-O` now opens it in the same bounded panel `?` uses: `↑↓` a line, `PgUp`/`PgDn` a page, `g`/`G` the ends, `/` searches **every line the ring kept** and not just the page on screen, `n`/`N` step between hits, `Esc` or `Ctrl-O` closes. It opens at the newest line and follows new output while the reader is at the end — a streamed answer keeps arriving under them — and stops following the moment they scroll up or jump to a match, so reading back during a running turn is not a fight with the cursor. Nothing else moves: the draft, the input history, the ring and the turn are exactly as they were, and there is nothing to scroll to that hcode did not itself print. When the ring has dropped its oldest lines the header says how many rather than looking complete. It is the same `draw()`/`paint()` path as every other frame, so the render property gate covers it and the static guard still holds: no fourth path writes terminal control.

- **The input line grew a cursor, and `?` tells you what the keys do.** Until now the composer's field was append-only: the cursor was always the end of the buffer, so `Ctrl-A`, `Ctrl-E`, `←`, `→`, `Alt-B`, `Alt-F` and `Alt-D` had nowhere to point and a typo four words back meant deleting four words. Every edit now goes through one `replaceRange()` primitive carrying a grapheme index, so those keys mean what they mean everywhere else, a paste lands where the cursor is instead of at the end, and `Ctrl-W`/`Ctrl-U` cut relative to it (`Ctrl-K` cuts the other way). The rendered field scrolls to keep the cursor visible and is byte-for-byte what it used to be when the cursor is at the end. **Multiline stopped depending on paste:** `Ctrl-J` inserts a newline, a trailing `\` turns `Enter` into one, and `Shift-Enter` is read in both encodings terminals send it in (`\x1b[13;2u`, `\x1b[27;2;13~`) — but nothing depends on the terminal being able to send it. **`Ctrl-R`** searches backwards through what you sent before and puts the match in the box rather than sending it; **`Ctrl-G`** hands the terminal to `$EDITOR` and takes it back with what you wrote (the composer suspends and resumes around it — the temp file is the CLI's, mode 0600, removed either way, and the composer still writes no draft to disk); **`Ctrl-L`** repaints the whole page from the transcript ring, which is the only thing in hcode that can repair a screen another program scribbled on; **`Ctrl-T`** is `/tasks`. **`?` on an empty input line** opens the key table as a panel — with anything typed it is just a question mark — and that table is one `KEY_HELP` constant that `/help`, the panel and the README table all render, so they cannot drift. Keys hcode deliberately does not bind are named in the README with the reason: `Ctrl-B` (hcode's turn runs in this process and cannot be detached; background work is started as background work), `Ctrl-P`/`Ctrl-N` (the arrows already do it and those keys belong to the slash list), `Shift-Tab` (permission is a decision, not a cycle). The panel is one bounded read-only widget — arrows and PgUp/PgDn scroll it, `/` searches it, Esc closes it — that paints through `draw()`/`paint()` like every other frame, so the render gate still covers it and no fourth path writes to the terminal.

- **The cheap answer stopped needing an argument.** A delegation that named neither a brain nor a tier was refused outright, which was right about never inheriting the foreign CLI's default and wrong about what to do next: the caller had to be told off before it could ask a question that was going to cost a fraction of a cent either way. hcode now reads the task, and when it is looking rather than building — searching, scanning, locating, listing, reading output — it takes the **smallest tier** and says so in the report it hands back (`claude subagent report (haiku — this reads as search work, so hcode took the smallest tier; a bigger brain is explicit — kind:"implement")`). A cheaper answer the caller did not ask for is only honest if the caller can see it was cheaper and ask again for more. Work that would *build* something is still refused with the exact call to write instead: saving money is the default, spending it stays explicit, and neither is ever a guess about what the caller meant.
- **Rewind's snapshot store reclaims by reference, not only by age.** The blob store had one way to shrink: blobs older than a week, swept when the store hit its 64 MB cap. A thread deleted this morning kept its copies for seven days, and a store full of week-old blobs that threads still name had nothing it could safely drop. A blob is now alive exactly as long as some thread's events still name it, counted by reading the session files themselves — which is what makes forks safe, since `forkAt` copies the parent's snapshot events into the child, so a shared blob is named twice and the count is a reference count with nothing to drift. Retiring a thread frees its private blobs and leaves the ones a fork inherited. The sweep runs at the end of a session (bounded: only when the store is at least a quarter full), when `put` needs room before it falls back to the TTL, and on demand with `hcode sessions --reclaim`. Reading the files *is* the algorithm on purpose: a refcount in a side file is a refcount that disagrees with reality after the first crash, and this store's failure mode has to be "keeps too much", never "deleted the file the owner was about to put back" — hence also a grace window, so a blob another process wrote moments ago is never collected mid-write. The seven-day TTL stays as the backstop for a store whose sessions were removed without anyone running a reclaim.
- **Permission became a rule book instead of a mood.** Until now the only durable thing an owner could say about a tool call was a pattern in `policy.json` `allow` — a list of yeses with no way to write a no, and no way to say "always ask me about this one". A rule is now a declared row: what it matches (`tool`, a `command` glob, a `path` glob) and what hcode does about it (`deny` / `ask` / `allow`), with a `why` that becomes the sentence the owner reads when it fires. Rules live in `.hcode/settings.json` at two levels — `~/.hcode/settings.json` for every project and the project's own — and the two files merge into one book whose conflicts are settled **by consequence, never by file order or apparent specificity: deny beats ask beats allow.** A user-level deny cannot be undone by a project-level allow, which is the whole point of having a user level: a repository cannot talk its way past a decision made once for every repository. A `deny` is evaluated **above the permission mode**, so `auto`, the session-only `all`, an `allow` in `policy.json` and an "always" clicked earlier in the same session all fail to reach past it — a mode says how much confirming the owner wants right now, not permission to undo something they already wrote down. An `ask` rule outranks `auto` for the same reason. A command pattern is matched against the whole line *and* every `;`/`&&`/`|` segment, so `npm run build && rm -rf dist` cannot hide a denied command behind a harmless prefix. An `allow` rule that names a command or a path also satisfies the network default for that one call — otherwise no rule could ever cover a push or a publish, which are network by nature — while a blanket `{"tool":"bash","action":"allow"}` names nothing and stays below the network policy rather than quietly repealing it. Enforcement is in the broker at the single point every tool call passes, not in the system prompt, and the model can neither read nor edit the file: `.hcode/` is on the secret-path blacklist. A malformed rule is dropped with a named problem rather than silently reinterpreted.
- **High-risk actions are gated by consequence, not by tool.** hcode's risk labels answered "what kind of tool is this" — read, write, network, destructive — which is the right vocabulary for a sandbox and the wrong one for a person: `bash` is one tool, and `ls` and `git push --force` are not one decision. Four classes of *outcome* are now read off the command itself before it runs — **spend** (a metered API, a cloud resource, another billed agent), **irreversible** (`rm -rf`, a force push, a hard reset, a forced overwrite), **exposure** (a push to a remote, a publish, a release, an upload) and **deletion** (files, branches, images, cloud objects) — and a hit asks by default, naming the class and the reason, because an owner told "this deletes things (rm removes files) and cannot be undone (rm -r/-f removes a tree with no undo)" can answer in a second, while one told "bash: destructive" has to go read the command themselves. Overlap is expected and both halves are said. The classification is a pattern table and deliberately not a model call: a gate that needs a brain fails when the brain is down, costs money to ask about money, and can be argued with. Segments are classified separately so `npm run build && rm -rf dist` is gated on its second half, and segments led by a read-only verb (`grep`, `echo`, `cat`, …) are skipped, so grepping *for* `git push` is not pushing. **A gate asks in every mode, `auto` and the session-only `all` included** — `all` means "stop confirming ordinary work", and deleting a tree was never ordinary work. A rule that names the command can cover one command the owner has already thought about; a blanket `{"tool":"bash","action":"allow"}` names nothing and cannot, and there is no setting that turns a class off wholesale, because "stop asking me about money" is exactly the decision that should be made one command at a time. A `deny` rule still outranks a gate, and the fixed boundaries (secret paths, root/home) are still checked before either. False positives are the intended failure direction.
- Delegating to a **flagship** brain is now the spend gate too. `--allow-flagship` / `allow_flagship:true` was the whole decision: it said the owner meant that model, and the helper started. Naming a brain and paying for one are two decisions, so the flag still names it and the owner is now asked before it runs — in the `delegate_agent` prompt, at `/claude --model fable`, and in `hcode task start`, which refuses with a `spend_gate` error rather than quietly billing when there is no one to ask.
- `/permissions` now shows the four modes and the whole rule book on **one screen**, and edits it there. A number moves a rule one notch — `deny → ask → allow → gone` — and `+ bash "git push*" ask` adds one; every edit is written straight back to the `settings.json` it came from, with the neighbouring keys (including the 0.1.0 `allow` list) carried through untouched, and takes effect on the next tool call without a restart. It stays a flat numbered list on purpose: no nested editor, no per-rule form, no wizard. A permission screen nobody can hold in their head is one nobody reads, and an unread rule book is not a gate. `/policy` prints the merged rules alongside the mode, network and sandbox.

- **`/tune` says what your own history argues for, with the count and the pointer for every claim, and changes nothing.** It reads the saved session logs and proposes three things. **The approvals you kept granting**, as `.hcode/policy.json` allow rules that will match again — `bash:npm test *` from the command and its subcommand, never the exact line with the commit message in it, and `write_file:src/**` from the directory — counting only what the *owner* was actually stopped for, because a `by:"policy"` approval cost nobody a keystroke and proposing a rule for it would be proposing a rule that already exists. **The requests you kept retyping**, grouped by shape rather than by words: paths and numbers are replaced first, so "run the suite for src/a.js" and "…for src/b.js" become one row — and that placeholder is precisely where `$ARGUMENTS` goes in the `/command new` line it suggests. **The big files that were read whole**, meaning a `read_file` with no `offset` and no `limit`, more than once and over 20KB on average, with the total they carried into the context: those want a range or a subagent. Every row says how many times it happened and one `session:seq` you can open, nothing is proposed from a single occurrence, and when the logs cannot support a class it says the data is thin — with the distinct-shapes count so you can see *why* — rather than filling the section with something plausible. It de-duplicates on `seq` exactly as `/cost` does, so a crash-recovered tail is not counted twice, and a session outside `--days` leaves no rows behind in the totals it is excluded from. It writes no file and edits no policy: a change to what hcode may do without asking is the owner's to make, and a tool that proposed and applied its own permissions would be the wrong shape however good the evidence. `hcode tune [--days N]` runs the same report from a script.

- **`/command new <name> <prompt>` makes a prompt you keep retyping into `/<name>`.** It writes `.hcode/commands/<name>.md` in the project, or `~/.hcode/commands/<name>.md` with `--user`, and from that moment `/<name> <args>` runs that prompt as an ordinary turn — `$ARGUMENTS` in the body is replaced by whatever follows the command, and a body without it gets the arguments appended rather than dropped. Nothing executes and nothing is fetched: the file is markdown the owner can read, edit in an editor, diff and commit, and running one is exactly the same as having typed its body, which is the only reason it needs no gate of its own. A command saved mid-session joins the `/` popup and `/help` on the next keystroke, because the catalog the composer holds is spliced rather than rebuilt. Precedence is stated everywhere it can be seen: a **built-in always wins** — a file named after one is still saved and listed, reported as shadowed at both the save and the list, and never dispatched — and a project file wins over a user file of the same name and says which one it shadows. `/command list` shows what there is, `/command show <name>` prints one. Bounds: a lowercase name up to 32 characters, 8,000 characters and 40 commands per directory (a longer procedure is a skill, not a command), and a refusal always carries the fix. The directory layout and the `description:` frontmatter are the ones Claude Code already uses, so existing command files copy in unchanged.

- **`/savetoken` is a session mode, not a piece of advice.** The owner's own token discipline had been a prompt pasted into every session; it is now a switch the session carries. `/savetoken` does exactly three things and nothing else: the system prompt gains a section saying that delegation is the default and this context is the exception — searching, scanning and any check across more than three files go to a subagent, a known file is read as a bounded range, and the answer is conclusion-first and short, with the escape written into it that correctness outranks the token rule, so hard debugging, architecture and security reasoning still read directly; a delegation that names neither a model nor a kind takes the **smallest** tier (`search`) instead of being refused, which is the one legitimate way past the 0.7 "no subagent runs on an unnamed brain" rule, because the session has already declared what an unqualified delegation means and the ledger still records the name; and the mode is appended to the thread as a `mode` event. That last part is what makes it a mode rather than a flag: it lives in the append-only log, so `hcode --resume` brings it back, a rewind fork inherits it, `/clear` keeps the mode while freeing the context, `/context` shows it, and a handoff ledger carries it on line 0 for `/continue` to restore. `/usedefault` cancels it. It never touches permission mode, the brain, the sandbox or the flagship rule — a mode that exists to spend less cannot buy a bigger helper.
- The codex subagent tiers name models the installed CLI still has. Checked against codex-cli 0.151.0: `search` → `gpt-5.6-luna` ("high-throughput, lower-latency work"), `mechanical` → `gpt-5.6-terra` ("balanced quality, latency, and cost"), `implement` → `gpt-5.6-sol` ("quality-first flagship, reasoning, and difficult coding work"). The 0.7 table named `gpt-5.1-codex`/`-mini`/`-max`, which that CLI now carries only as a migration key — a tier that resolves to a retired model is worse than no default, because the refusal then arrives from the foreign process instead of from hcode. `.hcode/settings.json` `{"subagentModels":{…}}` still replaces any cell.

- **A handoff became a work contract instead of a report file.** 0.5.0's `/handoff` wrote `HANDOFF-hcode.md` in the project root, refused to overwrite it, and had no reader: the next session had to find the file and interpret it, and a finished one sat in the root until someone deleted it by hand. It now files a **ledger** — `<project>/交接/hcode/active/hcode-<task>.md`, six numbered sections in a fixed order, with a machine-readable first line (`0. 模式: … | 状态: …`) that a reader can act on from the head of the file alone. The sections are goal and progress, next steps, verified versions and hashes, open questions, and a restart line, and every fact in them still comes only from the thread's own event log and from this process — no brain call, no cost, the same file for the same log. Three things are new in kind. **The restart line is generated, not typed:** a session already knows how it was started, so hcode writes the `cd`, the launcher (`hcode` when it is on PATH, otherwise the script that is actually running), the flags this session moved away from a plain `hcode`, and the environment variables that shape a session — with credentials filtered twice, by name and by value shape, because a ledger is a document the owner shares. It ends in `"/continue <task>"`, and `hcode "/continue parser"` now runs that as a slash command on a fresh session instead of sending it to the brain as a prompt, so the line is one paste and not two steps. **`状态` comes from the evidence:** anything unfinished or any unanswered `ask_user` makes it `active`, otherwise `done`; `/handoff done` and `/handoff active` override, because only a person can say the remaining item is somebody else's problem. **And `/continue` is the reader:** it files every `状态: done` ledger into `archive/YYYY-MM/` — the only thing that ever archives one, so a finished task cannot pile up in `active/` and an unfinished one is never touched however old it looks, and a ledger whose first line is unreadable is left exactly where it is — then opens the newest ledger still active (`/continue parser` filters by name), restores the mode it recorded, and prints goal, next and open. `/handoffs` lists what is active. Re-running `/handoff` for the same task overwrites the same file: one agent plus one task is one ledger, never a pile. Nothing is ever cleared or restarted for the owner; `/handoff` says the session can be restarted and stops there. `HCODE_HANDOFF_DIR` or `.hcode/settings.json` `{"handoffDir": "…"}` moves the directory.

- **Rewind: `esc esc` takes the conversation and the files back to an earlier point.** A checkpoint used to be a bookmark and nothing more — it recorded a seq and could not put anything back — so the only way out of a bad turn was to ask the brain to undo its own edits, from memory. Three pieces now make it real. **Every file-changing call is snapshotted before it runs:** `write_file` and `edit_file` copy the target as it stands into a content-addressed store beside the sessions (`~/.hcode/sessions/snapshots/`, mode 0600) and write a `snapshot` event carrying the hash before and, once the call is done, the hash after — which is what lets a restore tell hcode's own change from someone else's. It is bounded and says so: 2 MB per file, 64 MB per store, blobs past a week pruned first, and a file that does not fit is recorded as `skipped:"too_large"`/`"store_full"` rather than making a restore point quietly wrong. `bash` is deliberately not snapshotted — it can change files hcode cannot name in advance, and a rewind that claimed to undo a command it never recorded would be worse than one that says what it can restore. **`Session.forkAt(seq)`** copies the thread's events up to a chosen seq into a *new* thread through the same reader `--resume` uses, seals any call still open at the cut as cancelled (a transcript may never end on an unanswered `tool_use`, and hcode never re-runs a side effect it did not see finish), and leaves the original file untouched: going back is a fork, never a truncation, and both threads record where the branch happened. **The restore** puts back only the files hcode itself changed after that point, and only where the working tree still holds exactly what hcode last wrote — a file edited outside hcode since is named and left alone unless the owner says to overwrite it. `esc esc` on an idle composer opens the anchor menu: each request you made, each file hcode changed, and the thread's own checkpoints, with two anchors that would restore the same state collapsed into one row. There is no timing ambiguity with the single Esc — one Esc still closes a menu, closes the command list, or stops the running turn, and the pair is only read where a single Esc had nothing to do. `/rewind` is the same move for the readline path, pipes and anyone who prefers typing it.

- No subagent runs on an unnamed brain any more. `delegate_agent`, `/claude`, `/codex`, `hcode task start` and the new `/btw` all resolve one model before anything is spawned: either the call names it (`model:"sonnet"`, `--model sonnet`) or it declares the work and takes that tier — `search` → claude `haiku` / codex `gpt-5.1-codex-mini`, `mechanical` → `sonnet` / `gpt-5.1-codex`, `implement` → `opus` / `gpt-5.1-codex-max`. Before this, a delegation passed no `--model` at all and the foreign CLI answered on whatever its own default was, usually the most expensive brain on the machine, and nothing in the thread recorded which. The chosen model now rides in `child.spawn`, in the task state and in the `/tasks` line. A **flagship** brain — `fable` by name, plus whatever this session's own coordinator runs on — is refused as a helper unless the call says so on purpose (`allow_flagship:true`, `--allow-flagship`): a helper that costs what the coordinator costs is not a delegation. Every refusal is the exact call to write instead, in the caller's own syntax (the model reads `kind:"search"`, the owner reads `--kind search`), so a rejected delegation is one corrected retry and not a guess. `.hcode/settings.json` `{"subagentModels":{…}}` replaces any tier cell. A small local brain's tool schema omits the new fields (its window cannot pay for them) and hcode takes the smallest tier for it — still named, still recorded, still never the CLI's default.
- `/btw <question>` asks one aside. A one-off read-only subagent answers, the answer is printed and kept in the child ledger, and it is deliberately never appended to the conversation: a side question that would otherwise ride along in every later prompt now costs one call and nothing after it. `--agent claude|codex` picks the runner (the first installed one by default), `--kind`/`--model` picks the brain (`search` unless you say otherwise), and the aside writes its own thread under `~/.hcode/sessions/subagents/` that `/attach` can reopen.
- `/attach` grew an index and a way in. With no argument it lists this session's subagents — child id, runner, model, status, age, task — and the detached background conversations under it. `/attach <c-…>` opens a one-off subagent's own transcript (its prompt, its tool calls, what it answered), read-only; `/attach <task-…>` and `/attach <work-…>` are unchanged. The link is a new `session` field on `child.spawn`, so a helper's thread is addressable instead of surviving only as a 4,000-character summary.

- The composer remembers the conversation. It now keeps a **transcript ring** — a bounded, line-level record of everything it has put on the page (2,000 lines by default, `HCODE_TRANSCRIPT_LINES` or `new TerminalComposer({transcriptLines})` to change it) — so the page is a function of what was said plus the current frame, and can be repainted at any width. Three holes close with it. **A reflow no longer costs you the screen:** 0.6.0 fixed the stray rule fragments by scrolling the whole rewrapped page into the scrollback and starting from an empty transcript, so zooming the font left the owner staring at a blank page with the answer one scroll away; the ring repaints the same lines at the new width instead, and the page only goes to the scrollback when the ring is too short to put it back. **A frame that gives rows back fills them again:** closing the command list or a menu, or a taller terminal, used to leave a blank band where the transcript had been scrolled up to make room — those rows are transcript again and the ring refills them. **A shorter terminal keeps the newest lines:** a height change was a "repaint in place", so the frame simply landed further up the page and the rows that survived were the *oldest* ones the page happened to start with, with the newest painted over; every resize now repaints the page from the ring, and one branch does both axes. **And the region's last row stopped being dead:** a printed line ended in a newline, and at the bottom row of the scroll region that newline scrolls the page — the composer did not model it, clamped its next row one short, and every full screen ran one line behind what a fresh repaint paints, with a permanently blank bottom row. Transcript lines are now placed at an absolute row with an explicit scroll when they do not fit. Only colour survives into the ring, so a replayed line can never move the cursor or erase the screen; when the ring is full the oldest line is dropped and that line is simply no longer replayable — the page keeps working, it just cannot grow back past what is left.
- The render quality gate got its escape hatches taken away. `test/render-property.test.js` compared the whole screen against a fresh `draw()` of the same state *only while nothing had scrolled away*, and accepted the visible transcript as any unbroken run of what was printed — both concessions to a composer that could not model a line once it left the region. It now compares the whole screen every time and requires the page to be the **newest** unbroken run, which is what caught the dead bottom row: seed `0x516fd7cb` (a burst of eight, then the command list opening) painted eleven lines where the golden repaint painted ten and a blank. Verified red on the previous composer, green after over a widened `HCODE_RENDER_SEEDS` sweep.
- The composer stops breaking up the screen. Two faults were behind the stray rules and half-lines the owner kept seeing. **Resize:** the frame's rules and key hint can be wider than the terminal is about to become, so on a narrowing the terminal rewrapped them — a 96-column rule came back as 64 + 32 and every fragment stayed on the page, while the transcript slid by however many rows that added and every row number the composer held pointed at something else. 0.4.0 tried to mop this up by clearing from the old frame's top row down, which cannot reach fragments that reflow pushed *above* it. A width change now scrolls the whole page into the scrollback — where the owner can still read it — and repaints from an empty transcript; a height-only change (the frame's rows still say what they said) keeps the in-place repaint. **A growing frame:** opening the command list or a menu makes the frame taller, and it was painted straight over the last few transcript lines, which were then gone; worse, the next line of output overwrote one more, because the composer clamped its "next transcript row" into the shrunken region. The frame now scrolls the page up by the rows it is about to cover, so those lines move into the scrollback instead of being erased, and a full region is tracked as full — the next print scrolls rather than writes over the last line the owner can still see.
- A rendering quality gate, because "fixed the composer" has been said before and the breakage came back. `test/render-property.test.js` drives the real composer inside a real tmux PTY through seeded, interleaved event sequences — width resizes between 40 and 160 columns, CJK and emoji bracketed pastes, streamed output, the command list, arrow-key menus, approval prompts, activity ticks, attachments — and after each sequence asserts two invariants: the screen is what a fresh `draw()` of the same composer state paints, and above the scroll region there is no frame furniture, no gap and no overwritten line. Seeds are fixed so a failure reproduces exactly (`HCODE_RENDER_SEEDS=n` widens the sweep), and the failure message carries the whole event trace. A second, static test keeps the sink closed: outside `composer.js` no file in `src/` may write cursor movement, cursor visibility, erase-in-display or scroll-region control, so a fourth render path cannot quietly start painting the terminal behind the gate's back.
- `/cost` stopped being an alias for `/usage` and became the report across every saved session. It streams each `~/.hcode/sessions/*.jsonl` line by line — only header and `turn.end` rows are ever parsed, no file is read into memory whole — and de-duplicates on `seq` exactly as session replay does, because a crash-recovered thread rewrites its tail and adding up every line on disk came out about 50% high. It prints two things: the four classes the brain bills (uncached input, cache write, cache read, output) plus a **cost unit** total that weighs them against each other (uncached 1 · cache write 1.25 · cache read 0.1 · output 5), labelled as relative weights and never as dollars — hcode's gateways publish no price list, so a `$` figure would be invented; and then the whales, the ten sessions with the most cost units, each with its turn count, peak context (the largest prompt a single turn carried) and cache-read total. `hcode cost` runs the same report from a script, `--days N` (also `/cost --days N`) keeps only sessions started in that window, and the output is plain aligned text in pipes and print mode. Sessions written before the cache classes existed carry `{in, out}` only and read as zeros rather than crashing; a half-written line is skipped and counted, like `Session.load` does. `/usage` is unchanged: the turn this process just ran.

- Context pressure is now said out loud, once per tier, and never acted on. After every turn hcode compares the real prompt size the brain just billed (uncached input + cache write + cache read) against three tiers — 120K ⚠, 150K 🔶, 180K 🔴 — and prints one stderr line naming the tokens carried, the tier, and the way out: `/handoff`, then `/clear`, with `hcode --resume <id>` to reopen. It never clears or compacts the thread on the owner's behalf (that stays `--token-budget` compaction, which is independent of these tiers), it reports tokens and never invents a price for a gateway with no price list, and the highest tier crossed is the only one printed, so a jump straight past all three is one line, not three. Each notice is an `error{code:"context_pressure", tier, tokens}` event in the session JSONL; a compaction (or `/clear`, which starts a new thread) puts the ladder back to the bottom. Print mode and pipes record the event and print nothing. `.hcode/settings.json` `{"contextTiers":[…]}` sets other tiers.
- `/handoff [path]` writes a small handoff file — default `./HANDOFF-hcode.md`, refused if the file already exists — built only from the thread's own event log: what was asked (the first line of each turn's request), files changed, commands run, tool calls that never finished, the four-class token total, and the last thing the assistant said. No brain call, no cost, same file for the same log; a few hundred bytes to a few KB. Read it at the top of a fresh session after `/clear`, or `hcode --resume <id>` for the whole thread.

- Esc stops the running turn. It is the same abort as the first Ctrl-C (what was running is marked cancelled, the composer takes input again) but it never counts toward the 1.5s double press, so Esc can never exit hcode. What is open takes it first — an arrow-key menu backs out, the slash command list closes — an idle Esc does nothing and never clears the draft, and the readline path (no composer) gets it too through a stdin keypress; pipes and `--print` are untouched.

- Token use is counted in the four classes the brain actually bills: uncached input, cache write, cache read and output. The Anthropic `cache_creation_input_tokens`/`cache_read_input_tokens` fields were passed through the API layer but dropped on the way into the turn ledger; they now accumulate per turn, ride along in the `turn.end` usage payload (visible in the session JSONL), and `/usage` and `/cost` print one line per class plus the total. Old `{in, out}` readers keep their meaning — `in` is still uncached input — and a brain that reports no cache fields shows zeros.

- `hcode benchmark --polyglot` gains a `glm` runner — Claude Code pointed at z.ai's Anthropic-compatible endpoint (the owner's czo/czs setup; needs `~/.config/zai/api_key`) — and a `--models k=v,...` flag to pin per-runner models. Methodology fixes from the pilot review: the claude runner's model is now always pinned (`opus` unless `--models claude=...`; the pilot silently inherited the machine's `opus[1m]` default and was unreproducible), the per-exercise cash cap default rose from $0.5 to $2 (three of six pilot claude rows were budget-truncated at $0.50), and the lane passes the session's `--effort` down to the hcode child instead of letting it run the config default.
- Reasoning control for the DeepSeek brain: `--effort low` now sends `thinking: {type: "disabled"}` on the wire (probed live through the keyproxy: budget_tokens and reasoning_effort are ignored, thinking.type is honoured — a small probe went from 93 output tokens to 1). Medium/high keep the server default; non-DeepSeek gateways are untouched.

- First-run setup and `hcode setup` use the same arrow-key menu as the in-session `/brain` picker whenever the terminal can hold a composer; the numbered readline picker stays for pipes, dumb terminals and `NO_COLOR`. One `setupPrompter()` owns the choice.
- `hcode demo` ends with the arrow-key menu as a still frame — a composer that is never started draws the same rows `/brain` uses live, so the dialog shape review covers menus too.

## 0.3.9 — 2026-08-30

- Fix `hcode connect`/the remembered-tunnel path reporting "connected" when ssh's local port forward was up but the remote brain (port 8092) was down: `waitPort()` only proved ssh was listening locally, which it does the instant it starts regardless of the far end, so every request then failed with ECONNRESET after 3 silent retries.
- Add `probeBrain()`, a real HTTP probe through the tunnel (any HTTP response, even 401/404, counts as alive; ECONNRESET/ECONNREFUSED/timeout counts as dead) run right after `waitPort()` in `openTunnel()`.
- `hcode connect <name>` now exits non-zero with a `[failed]` message naming the dead remote host:port and the next steps (`ssh <user>@<host> 'ss -ltnp | grep 8092'`, `hcode doctor`) instead of printing "connected"; the remembered-tunnel path on plain `hcode` fails the same way instead of falling through into the agent's 3 retries. A tunnel opened by this code is always closed on probe failure — no dangling ssh child.
- `hcode doctor` adds a `tunnel` check (local port listening? brain reachable through it?) whenever a remembered SSH-tunnel Hoop is configured, and its `brain url` row now shows the tunnel URL instead of the misleading `https://api.anthropic.com` default in that mode.
- Hardened Hoops that set `AllowTcpForwarding no` in sshd (deliberate hardening, not misconfiguration) let ssh's `-L` bind locally and pass `waitPort()`, but reject every real forwarded connection with "administratively prohibited", which `probeBrain()` correctly reported as dead — `openTunnel()` now detects that exact stderr and transparently falls back to a per-connection ssh stdio bridge (`ssh ... node -e <BRIDGE>` piping a local TCP socket to the child's stdin/stdout, multiplexed over an SSH ControlMaster so it isn't a full handshake every time) instead of failing; `hcode connect`/the remembered-tunnel path print `(via ssh stdio bridge; sshd forbids port forwarding)` on success, and the down-hint now says "administratively prohibited" explicitly instead of "it is not running" when that's the real cause and the bridge itself couldn't reach the brain either.
- Fix `hcode doctor` crying wolf in tunnel mode: it demanded a local `ANTHROPIC_API_KEY`/`HCODE_API_KEY` even though keys stay on the Hoop and plain `hcode` needs none, and reported the tunnel `[failed]` just because nothing happened to be listening at that exact moment. The `key` row is now `[ok]` ("held by the Hoop … — nothing stored locally") whenever a default Hoop is configured, failing only when neither a key nor a Hoop exists; the `tunnel` row, when nothing is listening locally, opens one on demand through the same `openTunnel()` path plain `hcode` uses (stdio-bridge fallback included), probes it, reports `[ok]`/`[failed]` accordingly, and always closes it afterward — never leaving an ssh child behind.
- Fix the `brain` row of `hcode doctor` still pinging `cfg.baseUrl` (the untouched `https://api.anthropic.com` default) in tunnel mode, so it could read `[ok]` while the tunnel was dead or `[failed]` while plain `hcode` worked fine. The one-token ping now goes through the tunnel a real run would use — the already-listening local end, or the on-demand one while it is still open — and reads `answers (… ms) through the tunnel`; when the tunnel itself is down the row says `not probed — the tunnel above is not answering` instead of masking it with a ping somewhere else.
- Fix plain `hcode` dropping the owner into the first-run wizard (offering a browser sign-in nobody asked for) when the remembered Hoop failed to reconnect — the observed case was sshd closing the ssh master mid-handshake (`Connection closed by <ip> port 22`), a transient drop, not a missing setup. Three local changes, nothing on the Hoop: (1) a Hoop whose sshd forbids port forwarding is remembered as bridge-only (`hoopBridge: true` in config.json — a fact about the server, not a credential), so the next reconnect skips the doomed `-L` handshake and goes straight to the stdio bridge (one full handshake fewer per start; measured 7.4 s → 4.8 s); (2) if the ssh master dies with a transient message (connection closed/reset, kex failure, timeout — never "Permission denied" or "administratively prohibited") it is respawned once after 1.5 s, and the reconnect path retries `openTunnel()` once more on the same class of error; (3) when it still fails, `hcode` says `could not reconnect <hoop>`, tells the owner how to check (`hcode`, `hcode doctor`, `ssh gram@<host> true`, `hcode connect <other>` / `/logout`) and exits 1 — the wizard is for machines with no Hoop, not for a Hoop that is unreachable right now.
